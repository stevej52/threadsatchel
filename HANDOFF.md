# How ThreadSatchel works

ThreadSatchel lets an assistant pick up a project where an earlier conversation left off. You can ask “What did we decide?” and get back the passage where the decision was made. The archive lives on a computer you control.

**What gets remembered.** The importer accepts notes, conversation packets, and supported chat exports. Optional local capture can also collect supported Codex messages. Connecting a chat client gives it tools to use; saving a conversation still requires a capture source or an authorized save. SQLite keeps the original input, searchable message text, source information, and revisions. An exact repeat can reuse a receipt, an edit can create a revision, and uncertain overlaps stay available for review. A named handoff keeps instructions and files together. Saving a new version preserves the earlier one.

**How the assistant finds an answer.** Search starts with a short list of candidates. A saved handoff can rank above conversations that only mention its title. Repeated mentions can share one result. A message date helps distinguish a later correction from an earlier answer. The assistant can look at neighboring messages to see what changed, then ask for the exact paragraph, code block, or character range from the selected revision. For example, it can return just the function that fixed a bug, with its original spacing. A search and its follow-up reads share a default allowance of 2,000 tokens when they reuse the lookup ID. This limits what the tool sends into the conversation. The chat client handles its own context and billing.

**Where local AI helps.** If enabled, embeddings help find passages that use different vocabulary. A local model can also propose titles, summaries, and source-linked project briefs in the background. Image captioning uses explicitly configured folders. Generated descriptions help locate evidence. The original message or file is what the assistant should quote. Keyword search and exact reads work with the models switched off.

**What keeps the archive recoverable.** Before an inbox import that needs a backup, the sweep checks whether a verified snapshot already exists from the last hour. It retains four completed pre-import backups. A separate journal records which files each pass handled. After a controlled restore, files missing their receipts are held for review. Replay handles the oldest held file, checks database integrity, and stops on the first failure with the file identified. An optional scheduled backup verifies a copy at a destination you choose.

The read endpoint gives a client access to selected archive content. Saving is a separate capability. For remote access, the archive computer can connect outbound to a gateway you operate. Retrieved text reaches the requesting assistant, and remote requests and results pass through that gateway.
